    Auditoria documentação × código — 2026-09-22¶

    Tipo: histórico (análise datada; não substitui docs/architecture/CURRENT_STATE.md, project/STATUS.md ou project/TASKS.md, que continuam sendo as fontes vivas). Commit auditado: f35461a (working tree limpo no momento da auditoria). Método: 5 revisões independentes (firmware, backend, frontend, mobile, agendamento) comparando as afirmações de docs/, project/STATUS.md, project/TASKS.md e project/DECISIONS.md com o código real, arquivo por arquivo. Testes locais reexecutados de verdade (backend npm test, frontend npm run build, mobile flutter test/flutter analyze); firmware não foi buildado (pio run não executado).

    Resumo executivo¶

    A documentação está, no geral, honesta e bem alinhada ao código — a grande maioria das afirmações de "implementado" e das pendências críticas listadas foi confirmada linha por linha. Os problemas encontrados não são de "documento mentindo sobre o que existe", e sim de três tipos:

    1. Descrições arquiteturais um pouco otimistas sobre componentes que existem mas são mais finos/simples do que o texto sugere (ex.: CommandGateway).
    2. Um documento seriamente obsoleto (backend/README.md), que descreve uma versão muito anterior do backend.
    3. Achados novos não documentados em lugar nenhum — alguns potencialmente relevantes para segurança/produto — listados na seção final de cada bloco.
